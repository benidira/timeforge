# TimeForge → Programmatic SEO Engine: Implementation Blueprint

Written against the current codebase (Next 16 App Router, `src/content/*`, `src/lib/time/*`, `buildMetadata`,
`allPaths()`, `AdSlot`). Everything below extends those, it does not replace them.

---

## 0. Read this first: the risk that decides whether this works

Thousands of templated pages is exactly what Google's **scaled content abuse** policy and AdSense's
**low value content** policy target. The architecture below is only safe if each page carries information
that *cannot be obtained by swapping a word in a template*. So the blueprint bakes in four rules:

1. **Facts, not prose.** Page content is assembled from computed, page-specific data (real DST dates for
   that zone this year, real offsets to 12 hubs, a snippet that was actually executed, the next 5 runs of
   that cron expression). Filler paragraphs do not count.
2. **Quality gate decides indexability.** Every page computes a `uniqueFacts` score. Below the threshold it
   renders with `noindex` and is excluded from sitemaps. Nobody has to remember to do this manually.
3. **Staged rollout.** Ship ~300 pages first (Phase 1), watch Search Console "Indexed vs. Discovered/Crawled -
   not indexed" for 4-6 weeks, then widen. If Google refuses to index the first batch, 5,000 more won't help.
4. **Verified code only.** Snippets are executed in CI (Docker per language) and stamped with runtime
   version + date. Mass-generated, unrun snippets for 50 languages will contain wrong code, and wrong code
   in a developer tool is both a trust and a ranking problem.

Also: HowTo rich results were removed by Google in 2023 and FAQ rich results are now limited to government and
health sites. Keep the JSON-LD (it is cheap and harmless) but do not expect SERP features from it. The
existing rule in `seo.ts` ("only use FAQ when the same Q&A is visible") stays.

**Hub-page note (important, found while reading `src/app/[tool]/page.tsx`).** `[tool]` has
`dynamicParams = false`, so `/convert`, `/cron`, `/code`, `/timezones` (single segment) would hit it and 404
instead of falling through to the catch-all. Give each hub its own static `page.tsx` as listed above. Static
segments always win over dynamic ones. These hubs are also your best internal-link entry points.

**Catch-all vs. explicit directories.** The spec allows either. The dispatcher in section 4 keeps routing
logic in `lib/pseo` (testable without Next) and the `app/` tree thin. If you prefer explicit
`app/code/[language]/[task]/page.tsx` files, each is the same ~25 lines calling `resolvePage` with fixed
segments. The rest of the blueprint is unchanged.

## 2. Dataset type definitions (`src/data/types.ts`)

Rule: data files hold **facts**; behaviour (parse/format functions) lives in `lib/time` keyed by `id`, so
datasets stay plain JSON.

```ts
/* ---------- Time formats ---------- */

/* ---------- Cities / time zones ---------- */

  lat: number; lon: number;
  population: number;
  iana: string;                                     // "Europe/Paris"  (must pass Intl validation in CI)

  iana: string;
  stdOffsetMin: number;
  dstOffsetMin: number | null;
  abbreviations: { std: string; dst?: string };
  transitionsThisYear: { at: string; fromOffsetMin: number; toOffsetMin: number }[];
  observesDst: boolean;
}

/* ---------- Cron ---------- */
export type CronDialect = "unix" | "quartz" | "aws-eventbridge" | "kubernetes" | "github-actions";

export interface CronPreset {
  slug: string;                                     // "every-5-minutes"
  expression: string;                               // "*/5 * * * *"   (unix 5-field is canonical)
  title: string;                                    // "Cron: every 5 minutes"
  intent: string;                                   // the human sentence you'd google
  category: "interval" | "daily" | "weekly" | "monthly" | "yearly" | "business" | "special";
  dialects: Partial<Record<CronDialect, string>>;  // expression translated per dialect
```

Seeding sources: cities from GeoNames `cities15000` (CC-BY 4.0, **attribution required** on the site), with the
population threshold tuned so you land at 5,000+; DST/offset facts are never typed by hand, they come from
`Intl.DateTimeFormat` (same approach as your existing `zones.ts`) so they cannot go stale when tzdata updates.

## 3. Core pSEO types and the quality gate (`src/lib/pseo/types.ts`, `gate.ts`)

```ts
import type { FaqItem, Crumb } from "@/lib/seo";

export type PageType = "convert" | "timezone" | "code" | "cron";

export type ContentBlock =
  | { kind: "prose"; heading: string; paragraphs: string[]; facts: number }
  | { kind: "code"; heading: string; lang: string; code: string; expected?: string; verifiedOn?: string }
  | { kind: "table"; heading: string; head: string[]; rows: string[][]; facts: number }
  | { kind: "callouts"; heading: string; items: { title: string; body: string; severity: "info" | "warn" }[]; facts: number }
  | { kind: "steps"; heading: string; steps: { name: string; text: string }[] };

/** Serializable config for the client tool: NEVER pass functions across the server/client boundary. */
export interface ToolConfig {
  component: "timestamp" | "iso" | "timezone-converter" | "cron" | "world-clock" | "date-diff";
  initial: Record<string, string | number | boolean>;   // e.g. { from: "unix-seconds", to: "iso-8601" }
}

export interface PageModel {
  type: PageType;
  path: string;                       // "/code/python/timestamp-to-date"
  title: string;
  description: string;
  h1: string;
  intro: string;
  breadcrumbs: Crumb[];
  tool: ToolConfig;
  blocks: ContentBlock[];
  faq: FaqItem[];                     // must be rendered visibly (existing rule)
  related: { heading: string; links: { href: string; label: string }[] }[];
  uniqueFacts: number;                // computed by gate.ts from blocks
  indexable: boolean;
  lastModified: string;               // ISO date, from dataset version, NOT new Date()
  jsonLd: object[];
}

export interface Resolver {
  type: PageType;
  prefix: string;                                         // "code"
  /** Cheap descriptors (no content building) for sitemaps + generateStaticParams. */
  list(): { segments: string[]; tier: 1 | 2 | 3; indexable: boolean; lastModified: string }[];
  resolve(segments: string[]): PageModel | null;          // null -> 404
}
```

```ts
// src/lib/pseo/gate.ts
export const MIN_UNIQUE_FACTS: Record<PageType, number> = {
  convert: 10, timezone: 14, code: 8, cron: 10,
};
/** Sum of `facts` on blocks. A "fact" = a value derived from this page's own data, not a template word. */
export function scoreBlocks(blocks: ContentBlock[]): number {
  return blocks.reduce((n, b) => n + ("facts" in b ? b.facts : b.kind === "code" ? 3 : 0), 0);
}
export const isIndexable = (type: PageType, facts: number) => facts >= MIN_UNIQUE_FACTS[type];
```

What counts as a fact, per type (this is what makes pages genuinely different):

| Type | Page-specific, computed facts |
|---|---|
| timezone | UTC offset std/DST; this year's two DST transition instants; abbreviations; time difference table vs 12 hubs (computed); same-zone neighbour cities; country date-format sample via `Intl`; local 9-17 business hours expressed in UTC; population, coordinates |
| code | executed snippet + captured output; language's real precision; Y2038 answer *for that language*; negative-timestamp behaviour; the language's own gotchas; library vs stdlib alternative |
| convert | worked examples with real values in both formats; digit-length detection rule; range limits of the target format; format-specific pitfalls (Excel 1900 leap-year bug, FILETIME 100ns); precision loss when going ms → s |
| cron | next 5 run times (via existing `cron.ts`); per-dialect translations; field-by-field breakdown; the specific gotcha (DOM/DOW OR semantics, DST skipped/duplicated runs at 02:30) |

## 4. `app/[...slug]/page.tsx` (dispatcher, Server Component)

Next 16 notes baked in: `params` is a `Promise`; `generateStaticParams` returns only tier-1 pages;
`dynamicParams = true` lets everything else render on first request and then be cached (ISR);
`cache()` dedupes the resolve between `generateMetadata` and the page.

```tsx
// src/app/[...slug]/page.tsx
import type { Metadata } from "next";
import { notFound } from "next/navigation";
import { cache } from "react";
import { PageShell } from "@/components/pseo/page-shell";
import { resolvePage, tierOneParams } from "@/lib/pseo/registry";
import { buildMetadata } from "@/lib/seo";

type Params = { slug: string[] };

export const revalidate = 60 * 60 * 24 * 7;   // ISR: pages rebuild at most weekly; data is slow-moving
export const dynamicParams = true;            // tier 2/3 generated on demand, then cached

export function generateStaticParams(): Params[] {
  return tierOneParams().map((segments) => ({ slug: segments }));   // ~300 pages at build
}

const getPage = cache((slug: string[]) => resolvePage(slug));

export async function generateMetadata({ params }: { params: Promise<Params> }): Promise<Metadata> {
  const { slug } = await params;
  const page = getPage(slug);
  if (!page) return {};
  const base = buildMetadata({ title: page.title, description: page.description, path: page.path });
  // buildMetadata hard-codes index:true. The gate must be able to override it:
  return page.indexable ? base : { ...base, robots: { index: false, follow: true } };
}

export default async function Page({ params }: { params: Promise<Params> }) {
  const { slug } = await params;
  const page = getPage(slug);
  if (!page) notFound();
  return <PageShell page={page} />;
}
```

```ts
// src/lib/pseo/registry.ts
import { convertResolver } from "./resolvers/convert";
import { timezoneResolver } from "./resolvers/timezone";
import { codeResolver } from "./resolvers/code";
import { cronResolver } from "./resolvers/cron";
import type { PageModel, Resolver } from "./types";

// Prefix is the first segment; hub pages live in their own static page.tsx (see section 1).
export const RESOLVERS: Resolver[] = [convertResolver, timezoneResolver, codeResolver, cronResolver];
const byPrefix = new Map(RESOLVERS.map((r) => [r.prefix, r]));

export function resolvePage(slug: string[]): PageModel | null {
  const [prefix, ...rest] = slug.map((s) => s.toLowerCase());
  if (slug.some((s, i) => s !== s.toLowerCase())) return null;      // canonical form only: no case duplicates
  return byPrefix.get(prefix)?.resolve(rest) ?? null;
}

export function tierOneParams(): string[][] {
  return RESOLVERS.flatMap((r) =>
    r.list().filter((e) => e.tier === 1).map((e) => [r.prefix, ...e.segments]));
}
```

### One complete resolver: `/code/{language}/{task}`

```ts
// src/lib/pseo/resolvers/code.ts
import { LANGUAGES, getLanguage } from "@/data/languages";
import TASKS from "@/data/tasks.json";
import { buildCodeBlocks, buildCodeFaq, buildCodeRelated } from "../content/code-blocks";
import { isIndexable, scoreBlocks } from "../gate";
import { codeJsonLd } from "../schema";
import type { PageModel, Resolver } from "../types";

const TOP_LANGS = new Set(["javascript", "python", "java", "go", "php", "csharp", "rust", "ruby", "swift", "kotlin"]);
const TOP_TASKS = new Set(["get-current-timestamp", "timestamp-to-date", "date-to-timestamp"]);
const DATA_VERSION = "2026-10-01";           // bump when snippets are re-verified

export const codeResolver: Resolver = {
  type: "code",
  prefix: "code",

  list() {
    return LANGUAGES.flatMap((lang) =>
      Object.keys(lang.tasks).map((task) => ({
        segments: [lang.slug, task],
        tier: (TOP_LANGS.has(lang.slug) && TOP_TASKS.has(task) ? 1 : 2) as 1 | 2,
        // A page without an executed snippet has nothing unique to say: keep it out of the index.
        indexable: Boolean(lang.tasks[task as keyof typeof lang.tasks]?.expected),
        lastModified: lang.runtime.verifiedOn,
      })),
    );
  },

  resolve([langSlug, taskId, ...extra]) {
    if (extra.length) return null;
    const lang = getLanguage(langSlug);
    const task = (TASKS as Record<string, { title: string; verb: string; question: string }>)[taskId ?? ""];
    const snippet = lang?.tasks[taskId as keyof typeof lang.tasks];
    if (!lang || !task || !snippet) return null;

    const path = `/code/${lang.slug}/${taskId}`;
    const blocks = buildCodeBlocks(lang, taskId, task, snippet);
    const uniqueFacts = scoreBlocks(blocks);
    const faq = buildCodeFaq(lang, task);

    const page: PageModel = {
      type: "code",
      path,
      title: `${task.title} in ${lang.name} (with runnable example)`,
      description: `${task.question} in ${lang.name} ${lang.runtime.version}: tested code, expected output, and the ${lang.name}-specific pitfalls (Y2038, precision, time zones).`,
      h1: `${task.title} in ${lang.name}`,
      intro: `${task.question} ${lang.name} stores time with ${PRECISION[lang.precision]} precision. ` +
             `The example below was executed on ${lang.name} ${lang.runtime.version} on ${lang.runtime.verifiedOn}.`,
      breadcrumbs: [{ name: "Home", href: "/" }, { name: "Code", href: "/code" }, { name: lang.name, href: `/code/${lang.slug}` }, { name: task.title }],
      tool: { component: "timestamp", initial: { unit: lang.precision === "s" ? "s" : "ms" } },
      blocks,
      faq,
      related: buildCodeRelated(lang, taskId),
      uniqueFacts,
      indexable: isIndexable("code", uniqueFacts),
      lastModified: lang.runtime.verifiedOn ?? DATA_VERSION,
      jsonLd: [],
    };
    page.jsonLd = codeJsonLd(page);
    return page;
  },
};

const PRECISION = { s: "second", ms: "millisecond", us: "microsecond", ns: "nanosecond" } as const;
```

`buildCodeBlocks` returns, in order: (1) the verified snippet + expected output, (2) a "language facts"
callout list built from `lang.y2038`, `lang.negativeTimestamps`, `lang.tzDatabase`, `lang.caveats`
filtered to this task, (3) a "stdlib vs. library" table when `lang.kind === "language"` and alternatives exist,
(4) a steps block. Each carries a `facts` count equal to the number of distinct data-derived values it
prints. Resist the urge to add generic "Why timestamps matter" paragraphs: they raise word count and lower
quality.

Page blocks: offset summary table → this year's DST transitions (or an explicit "does not observe DST since
YYYY" statement computed from the data) → difference-to-hubs table → "9-to-5 here is HH:MM-HH:MM UTC" →
neighbour cities in the same zone → country formats. Tier policy: `population ≥ 1M` → tier 1 (SSG), `≥ 250k` →
tier 2 (ISR), rest → tier 3, **indexable only if the city has a distinct fact beyond its zone** (otherwise
`paris-fr` and `lyon-fr` are 90% identical and you should instead index one `/timezones/europe-paris` zone page
and list the cities on it). Practical recommendation: index zone pages (~420 IANA zones) plus cities ≥ 500k;
keep the other 4,000 as `noindex, follow` search targets that still help users via on-site search.

## 6. Segmented sitemaps with an index

Next's `app/sitemap.ts` + `generateSitemaps()` can chunk, but it cannot emit a sitemap *index*, and file names
are fixed to `/sitemap/{id}.xml`. Route handlers give full control. **Delete `src/app/sitemap.ts`** (it would
clash with `app/sitemap.xml/route.ts`).

```ts
// src/lib/pseo/sitemap-registry.ts
import { allPaths } from "@/lib/routes";
import { SITE, absoluteUrl } from "@/lib/site";
import { RESOLVERS } from "./registry";

export const URLS_PER_SITEMAP = 5_000;           // protocol limit is 50,000 / 50 MB; smaller = faster, easier to debug

export interface SitemapEntry { path: string; lastModified: string }
export interface SitemapGroup { name: string; entries(): SitemapEntry[] }

export const GROUPS: SitemapGroup[] = [
  { name: "pages", entries: () => allPaths().map((path) => ({ path, lastModified: SITE.contentUpdated })) },
  ...RESOLVERS.map((r) => ({
    name: ({ convert: "convert", timezone: "timezones", code: "code", cron: "cron" } as const)[r.type],
    // Only indexable pages. Gated pages are noindex and MUST NOT be listed.
    entries: () => r.list().filter((e) => e.indexable)
      .map((e) => ({ path: `/${[r.prefix, ...e.segments].join("/")}`, lastModified: e.lastModified })),
  })),
];

export function chunksOf(group: SitemapGroup): SitemapEntry[][] {
  const all = group.entries();
  const out: SitemapEntry[][] = [];
  for (let i = 0; i < all.length; i += URLS_PER_SITEMAP) out.push(all.slice(i, i + URLS_PER_SITEMAP));
  return out.length ? out : [[]];
}

const esc = (s: string) => s.replace(/&/g, "&amp;").replace(/</g, "&lt;");
export const urlsetXml = (entries: SitemapEntry[]) =>
  `<?xml version="1.0" encoding="UTF-8"?>\n<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">\n` +
  entries.map((e) => `<url><loc>${esc(absoluteUrl(e.path))}</loc><lastmod>${e.lastModified}</lastmod></url>`).join("\n") +
  `\n</urlset>`;
```

```ts
import { GROUPS, chunksOf, urlsetXml } from "@/lib/pseo/sitemap-registry";

export const revalidate = 86400;
export async function GET(_: Request, { params }: { params: Promise<{ file: string }> }) {
  const { file } = await params;
  const m = /^([a-z]+)-(\d+)\.xml$/.exec(file);
  const group = m && GROUPS.find((g) => g.name === m[1]);
  const chunk = group && chunksOf(group)[Number(m![2]) - 1];
  if (!chunk) return new Response("Not found", { status: 404 });
  return new Response(urlsetXml(chunk), { headers: { "Content-Type": "application/xml; charset=utf-8",
    "Cache-Control": "public, s-maxage=86400, stale-while-revalidate=604800" } });
}
```

`lastmod` comes from dataset verification dates, never `new Date()`. Stamping every URL with today's date on
every build teaches Google to ignore your lastmod. Update `robots.ts` to emit `Sitemap: {SITE.url}/sitemap.xml`
and keep `Disallow` empty (do not block the noindex pages in robots.txt, or Google can't see the noindex tag).

## 9. Ads, consent, `ads.txt`

```ts
// src/lib/site.ts  (extend)
export const ADS = { client, slots: {
  "header-banner": env("NEXT_PUBLIC_ADSENSE_SLOT_HEADER"),
  "in-content":    env("NEXT_PUBLIC_ADSENSE_SLOT_IN_CONTENT"),
  "sticky-bottom": env("NEXT_PUBLIC_ADSENSE_SLOT_STICKY"),
} } as const;
```

- **Layout stability.** Each placement gets a fixed `min-height` (header 90px / in-content 280px / sticky 50px)
  so late-loading ads cause no layout shift. Keep rendering *nothing* when no client ID is set (current behaviour).
- **Sticky bottom.** Dismissible, hidden on viewports <360px tall, never covering the tool's primary button,
  and never rendered until consent resolves. Google's policies restrict ads that obstruct content; keep it small.
- **Consent (required for EEA/UK/CH with AdSense).** Use a Google-certified CMP implementing IAB TCF v2.2:
  Google's own *Privacy & messaging* (free, configured inside AdSense) is the lowest-effort option. Load the
  CMP script first, load `adsbygoogle.js` after, and treat "no consent" as non-personalised ads rather than
  no ads. This is also the moment to add the nonce-based CSP that `next.config.ts` currently defers
  (`script-src` nonce + `pagead2.googlesyndication.com`, `googleads.g.doubleclick.net`, `fundingchoicesmessages.google.com`).
- **`ads.txt`:**


Remember that AdSense reviews the *site*, not your architecture. Apply for approval when the Phase 1 pages
(~300, high-quality) are live, **before** the long tail exists. Approval on a site with 5,000 templated pages is
much harder than on one with 300 solid ones.

## 11. Rollout plan

1. **Foundation (no new URLs):** `lib/pseo` types, gate, registry, `PageShell`, sitemap index, tests, `initial` prop on tools.
2. **Phase 1 (~300 pages):** 10 languages × 3 tasks (30), 12 formats' top pairs (~40), cron presets (30), ~60 zones/large cities. Run snippet CI. Submit sitemap index in Search Console.
3. **Measure 4-6 weeks:** indexed ratio, impressions per template. Kill or rewrite templates Google skips.
4. **Phase 2:** remaining tasks/languages (verified), cron to 100+, zone pages for all IANA zones, cities ≥ 500k.
5. **Phase 3 only if Phase 2 indexes well:** long-tail cities, hub-to-hub difference pages. Apply for AdSense after Phase 1 is indexed.
